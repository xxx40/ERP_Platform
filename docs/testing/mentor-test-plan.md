# 一期 ERP 问答平台测试数据与验收说明

## 1. 数据构造原则

- `phase1_knowledge_cases.json` 包含 20 个采购订单、收料、入库、异常和权限案例，共 40 个自然语言问题。
- 所有案例均带有 `synthetic=true`、唯一标识和“合成测试资料”声明，不代表公司正式制度。
- 订单事实来自统一采购数据 API 的 SQLite Mock 数据，经租户、组织和本人范围校验，不在前端硬编码。
- 文档案例只有上传到实际 WISE/IMA 测试知识库后，才能证明外部知识检索链路；本地结构测试只能证明数据规模、映射和评估程序有效。

## 1.1 当前权限模型

| 对象 | 当前规则 | 尚缺能力 |
|---|---|---|
| 用户身份 | 后端读取 `X-User-Id / X-Tenant-Id / X-Org-Code`，缺失时使用 demo 默认值 | 尚未验证 SSO/JWT，请求头目前可由调用方伪造 |
| 组织级订单 | 必须匹配订单的租户和采购组织，同组织用户可查询 | 尚无岗位、角色和字段级控制 |
| 本人级订单 | 在租户和组织匹配基础上，`owner_user_id` 还必须等于当前用户 | 负责人代理、上下级授权等规则尚未定义 |
| 采购分析 | 按租户和采购组织隔离，当前不校验具体用户 | 尚无指标级、供应商级和金额字段权限 |
| 会话与 Trace | 首次请求绑定用户、租户、组织，之后必须完全一致 | 依赖可信身份接入后才具备生产安全性 |
| WISE/IMA 文档 | 使用系统级 API 凭据查询固定知识库 | 没有传递当前用户身份，也没有本地执行文档 ACL |
| 前后端 | 前端当前不发送身份令牌，使用后端 demo 身份 | 需要接 SSO，并禁止生产环境回退到 demo 身份 |

## 3. 权限 API 手测

前端当前不发送身份令牌，默认使用 `demo-user / tenant-demo / ORG-DEMO-001`。权限测试应通过 API 请求头执行：

```powershell
$body = @{ message = "PO202607403 当前状态是什么？" } | ConvertTo-Json
$headers = @{
  "X-User-Id" = "restricted-user"
  "X-Tenant-Id" = "tenant-demo"
  "X-Org-Code" = "ORG-DEMO-001"
}
Invoke-RestMethod -Method Post -Uri "http://127.0.0.1:8001/api/v1/chat" `
  -Headers $headers -ContentType "application/json; charset=utf-8" -Body $body
```

使用 `restricted-user` 查询 `PO202607403` 应成功；改成 `demo-user` 应无权限；把组织改成 `ORG-NOT-ALLOWED` 也应无权限。

## 4. 需要外部准备的资料

1. 将 20 个合成案例上传到专用 WISE 或 IMA 测试知识库，或由业务负责人提供 20 份已脱敏且允许测试的正式资料。
2. 业务负责人确认每个案例的预期答案、制度口径、异常阈值和生效版本；合成案例只能验证系统能力，不能证明业务规则正确。
3. 提供至少五类测试身份：采购主管、采购员 A、采购员 B、跨组织用户和无权限用户，并给出字段级可见性矩阵。
4. 提供知识平台的用户级 ACL 传递方式或服务端代查规则。当前 WISE/IMA 调用只使用系统级 API 凭据。
5. 如需验证真实超时、限流和服务异常，提供隔离的测试知识库账号、故障注入代理或测试环境；不要通过破坏共享生产凭据进行验证。

## 5. 自动验证边界

- pytest 已覆盖知识未命中、检索改写轮次、订单不存在、订单无权限、会话串用、请求总超时、外部服务超时映射和写操作拒绝。
- `run_evaluation.py` 验证真实 HTTP 链路、意图、状态、错误码、订单编号、来源数量、引用一致性、Trace 完整性和 Trace 错误 Span。
- 真实文档答案质量仍需要上传后的知识库检索结果和业务负责人评分，不能用本地 Mock 替代。
