# ERP 问答平台最终评测报告（2026-08-04）

## 1. 评测结论

本轮使用真实后端 HTTP 链路执行 **48 个场景、50 轮对话**，综合通过 **47/48（97.9%）**。意图识别、业务 Tool 输出、模型回答检查和安全场景均达到 100%；唯一未通过项是“经营分析＋制度依据”的复合问题，在知识源配额或证据不足时被可信校验器停止，没有把无依据内容包装为成功答案。

发布门禁 `release-gate-v4` 本轮状态为 **未通过**。原因不是权限或业务事实错误，而是引用通过率 93.3%、Grounding 通过率 85.7%，低于门禁要求的 95%。该结果作为已知问题保留，不能改写成“100% 通过”。

## 3. 评测链路

```text
固定问题集
→ 调用真实 /api/v1/chat
→ 校验意图、状态、错误码和结构化组件
→ 校验引用、Grounding 和业务事实隔离
→ 校验 Tool 调用、工作流节点与本地 Trace
→ 汇总耗时、Token、分类通过率
→ release-gate-v4 发布门禁
```

- **本地 Trace 是硬校验依据**：验证工作流节点、Tool、错误 Span、关键链路和请求闭环。
- **Langfuse 是可选观测出口**：只导出白名单指标和脱敏标识，不作为本地评测通过的唯一依据；未配置 Langfuse 时，本地 Trace 与评测仍可运行。
- **外部服务与本地测试分离**：`pytest` 使用 Stub/Mock，不调用真实 WISE、IMA 或模型网关；HTTP 评测使用当前已启动的真实后端链路。

## 5. 唯一失败项与修复方向

- **用例**：`COMPOSITE-01`，本季度采购分析，并说明相关制度依据。
- **正确部分**：意图识别为复合问答；经营分析 Tool、工作流和 Trace 均通过。
- **失败点**：知识通道没有形成满足门禁的引用证据，最终返回 `ANSWER_VERIFICATION_FAILED`，状态为 `not_found`。
- **为什么这样是可信的**：系统保留了业务分析结果，但没有在缺少制度证据时生成伪引用。
- **后续修复**：为 WISE/IMA 增加稳定测试知识库与配额监控；复合任务允许保留“已确认业务事实”，并将制度部分明确降级为“当前无可用依据”；补充该降级响应的回归断言。
