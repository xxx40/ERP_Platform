> 本报告是本轮唯一保留的阶段性评测说明。原始结构化结果见 `docs/testing/evaluation-result-20260804.json`；原始逐案例结果不纳入 Git，避免提交本地运行产物。

## 2. 评测链路：本地 Trace 为事实源，Langfuse 为可选外部观测

一次测试请求的链路如下：

```text
测试问题/会话上下文
  → FastAPI /api/v1/chat
  → Agent 语义路由与任务计划
  → Tool Discovery / 权限 / 参数校验
  → 业务 Tool 或 WISE/IMA 检索
  → 事实与证据校验
  → 结构化回答
  → 本地 TraceRecorder 记录 request_id + spans + 模型状态 + token
  →（配置 Langfuse 时）异步 HTTP Exporter 上送 Langfuse
```

本轮指标中的 `trace_pass` 来自后端本地 Trace 查询接口（`/api/v1/traces/{request_id}`），因此可以确认 **本地 Trace 链路已工作**。代码支持在 Langfuse 配置完成时异步导出，但本次报告不把“Langfuse 外部页面可见”冒充为已核验事实；外部服务是否接收成功仍应在部署环境查看 Langfuse 控制台。

Trace 重点记录：路由节点、Tool 调用、模型 HTTP 状态、输入/输出 Token、检索轮次、证据校验、工作流错误和最终状态。导出失败不会阻塞用户请求。

### 3.1 评测不是只看“答没答出来”

每个场景按以下层次检查：

1. **路由层**：整句语义是否命中 document/order/analytics/mixed/composite/clarify/general/reject；
2. **状态层**：是否返回预期的 success、needs_clarification、rejected、not_found 或 unauthorized；
3. **业务结果层**：订单号、订单卡片、订单列表、分析卡片和指标结构是否完整；
4. **证据层**：知识类问题是否有来源，复合问题是否存在事实与依据支撑，答案是否超出证据；
5. **治理层**：权限、Tool 白名单、只读边界、预算/超时/重试和 Trace 是否正常；
6. **性能层**：端到端耗时、P95 耗时、输入/输出/总 Token，用于发现长尾和成本风险。

## 5. 唯一失败与修复方向

| 项目 | 内容 |
|---|---|
| 场景 | `COMPOSITE-01`：本季度采购分析，并说明相关制度依据 |
| 路由结果 | 预期 composite，实际 composite；意图路由正确 |
| 失败位置 | 事实与知识证据汇聚后的 Answer Verification |
| 返回结果 | `not_found`，错误码 `ANSWER_VERIFICATION_FAILED`，来源数 0 |
| 为什么不是“答错” | 知识通道没有足够制度证据时，系统选择停止，不用模型常识补写制度结论 |
| 当前修复方向 | 补充/校验 WISE/IMA 中经营分析制度类文档；增加复合问题证据覆盖；保持“证据不足即停止”的安全策略 |

这次失败暴露的是**知识证据覆盖不足**，不是业务数据 Tool 不可用，也不是语义路由错误。它正是发布门禁存在的意义：阻止“事实有了、依据没有，却生成一段看似完整答案”。

## 7. 结论与下一轮建议

### 已验证

- 语义路由不是关键词索引：48 个场景意图识别全部通过；
- 业务事实走只读数据能力，文档问题走知识检索，复合问题分通道获取；
- 未接入或不匹配的数据能力不会伪造 Tool，也不会改查文档冒充答案；
- 追问、无权限、写操作、未找到和无证据均能收敛到明确状态；
- 每个评测请求均留有可查询的本地 Trace，Langfuse 作为可配置外部观测出口。

### 优先改进

1. 为经营分析类复合问题补齐 WISE/IMA 制度证据，并增加同类回归用例；
2. 优化文档检索长尾，重点观察 P95 耗时和复合问题 Token 峰值；
3. 在部署环境确认 Langfuse 接收、Trace 关联和告警面板；
4. 增加库存、生产、销售等已授权只读数据集后，再扩展对应开放式业务问题测试集。
