# Brainstorming

以事实梳理开始，再按输入成熟度进行问题界定、方向探索、方案比较或方案检验，暂停或结束时完成
结论收束；不强制固定问卷、阶段顺序、候选数量或持久化产物。

## 触发与退出

- 用户明确要求头脑风暴、探索问题、比较候选或挑战已有方案时使用。
- 用户只表达评价、建议、可能性或带路径的模糊反馈，且没有要求写入时，由执行契约路由到这里。
- 用户已经明确要求修改、创建、实现、修复、删除或保存，或明确认可最近一条写明具体持久化动作
  与范围的实施方案或授权询问时，不进入或立即退出本 skill，并把相应目标交回执行契约。
- 混合请求按独立目标拆分；一个目标的写入授权不得扩散到相邻的模糊反馈。

## 权限边界

本 skill 严格只读。可以搜索、读取、比较并运行不会改变状态的检查，但不得创建或修改任何文件、
OpenSpec artifact、外部记录或版本控制状态。仅形成讨论共识，或只确认未写明具体持久化动作与
范围的方向、目标、验收结论，都不等于写入授权。

用户要求保存或实施结论时，先做结论收束，整理当前事实和决定，再退出本 skill。后续写入由新的
明确动作请求，或对写明具体持久化动作与范围的实施方案或授权询问作出的明确认可触发；认可按
上下文语义判断，不依赖固定词表。本 skill 不直接执行。

## 热上下文复用

- 优先复用当前上下文已经确认的仓库事实、决定和状态快照；只在新证据可能改变结论时重新调查。
- 用户表达对当前结论或继续当前方向的明确认可，或追问已读取事实时，不重新读取相同代码、
  reference 或状态。
- 会话恢复或压缩后，仅在关键事实没有保留、无法唯一确定或可能过期时刷新；不要为恢复逐字历史
  而重复加载无关材料。

仅在通过 `/opsx:explore` 调用、用户明确指定 change，或热上下文中已有唯一 active change，且当前
没有可复用的同 change 状态快照或快照已失效时，读取并遵守
`references/openspec-context.md`。仓库中仅存在 `openspec/` 目录、开始新一轮对话或上述明确认可
都不是加载条件。

## 自适应讨论

### 事实梳理

每次调用都先区分用户目标、仓库可查事实、外部未知和问题成熟度。事实梳理可以缩成一句确认，
但不能完全省略；先查代码、配置和历史，不把仓库可查事实反问用户。

### 问题界定

只有目标、成功标准或硬约束仍会改变讨论方向时才做问题界定。输入充分时跳过。

### 方向探索 / 方案比较 / 方案检验

根据当前输入选择起点，并允许随新证据切换：

- `方向探索`：只有早期想法或问题空间尚未成形时，形成有意义的方向、线索或下一项关键决定；
  不为满足格式凑固定数量的方案。
- `方案比较`：已有多个真实候选时，比较决定因素、代价和适用条件，并给出推荐或条件式推荐。
- `方案检验`：已有明确方案或当前最优方向时，检查关键假设、失败路径、迁移、回滚、缓解措施和
  残余风险，不擅自把任务改成重新设计。

Agent 应基于证据推荐当前最优候选并主动挑战它。会改变目标、范围、验收、架构边界或外部契约的
实质决定留给用户确认；不改变这些边界的低风险、可逆默认值可以说明假设后采用。

### 讨论质量

- 主题横跨多个可独立交付的部分时，先拆清边界、依赖和先后关系，再聚焦当前要解决的一部分；
  不把超大主题硬塞进一个方案。
- 讨论现有代码时，先理解并遵循已有结构与约定；只提出直接服务当前目标的改进，不顺带重构。
- 按实际需要设计，不预设尚未出现的功能；候选中的模块应职责清楚、接口和依赖明确，并能独立
  理解和验证。

### 对答收敛

只在外部决定会实质改变方向时提问；没有真实未知时跳过。默认每轮一个问题，并给出必要判断依据
或推荐；只有二至三个问题彼此不依赖、属于同一决策链且用户可基于当前信息同时回答时，才可合并
到一轮。任何后续问题依赖前一个答案时都拆到下一轮。

可使用当前 Agent 环境提供的用户提问工具；工具不可用或不适合开放式回答时使用普通对话。无论
采用哪种方式，都不得合并存在依赖的问题，也必须等待用户回答后再继续。

收到回答后，更新已确认的决定、假设与开放项，再选择下一项关键决定；若答案引出新分支或推翻
已有假设，回到相应讨论阶段继续。仍有会实质改变方向的外部决定时保持这一循环。准备以一致结论
结束时，复述共享理解并请用户确认或纠正；未确认则继续讨论，用户主动暂停时带开放项进入结论收束。

### 结论收束

讨论暂停、结束或准备转入写入流程时，简要汇总：

- 已确认的目标与仓库事实；
- 真实候选、推荐和主要权衡；
- 用户已经确认的决定；
- 尚未解决的未知项；
- 需要另行明确授权的具体下一步。

不得把“讨论完成”表述为“实现完成”。
